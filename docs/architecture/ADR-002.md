# ADR-002 - Concurrency Strategy

## Context

Concurrent financial transactions can lead to race conditions, double spending, and deadlocks.

## Decision

The ledger system uses:

- PostgreSQL row-level locking (`SELECT ... FOR UPDATE`)
- Consistent lock ordering for multi-account transactions

## Consequences

### Advantages

- Prevents double spending
- Ensures serializable balance updates
- Avoids deadlocks through deterministic locking order

### Trade-offs

- Reduced throughput under heavy contention
- Longer transaction wait times during concurrent operations
